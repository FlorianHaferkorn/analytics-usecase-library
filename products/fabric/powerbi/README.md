# Microsoft Fabric / Power BI Implementation

Tool-specific implementation of the ActionReady Analytics Framework on **Microsoft Fabric + Power BI**.
Core framework meaning stays in `core/`; this folder is the single entry for Fabric/Power BI implementers.

---

## Start here (five steps)

| Step | What | Where |
|---|---|---|
| 1 | Understand the architecture | [`docs/architecture/README.md`](../../../docs/architecture/README.md) |

## Folder structure

| Folder | Role | Edit? |
|---|---|---|
| `orchestrator/` | PowerShell scripts that generate and orchestrate the full model (TMDL + reports) | Yes — source |
| `tooling/` | Fabric-specific validators, generators, page scaffold, theme tools, migration audit | Yes — source |
| `docs/` | Architecture best practices, TMDL conventions, PBIR structure, reference docs | Yes — source |
| `blueprints/` | Domain blueprint YAML files that drive semantic model generation | Yes — source |
| `templates/` | PBIP template skeletons for reports | Yes — source |
| `deployment/` | Fabric workspace setup and Azure Pipelines | Yes — source |
| `dist/` | **GENERATED** — semantic models and reports; regenerated by `orchestrate_full_model.ps1` | **No — do not edit manually** |

## Key workflows

### Generate the full model (measures + reports)

```powershell
# Run from repo root
.\products\fabric\powerbi\orchestrator\orchestrate_full_model.ps1
```

Output lands in `products/fabric/powerbi/dist/`. Each domain gets a `<Domain>.SemanticModel/` folder; each use case gets a `<ID>_<Name>.Report/` folder.

### Generate TMDL measures for a single use case

```powershell
# Run from repo root
.\tooling\generator\generate_tmdl_measures.ps1 -UseCase COM-001 -OverwriteExisting
```

### Validate Fabric output

```powershell
# Fabric-specific checks (measures vs KPI, TMDL, DAX best practices, schema versions)
.\products\fabric\powerbi\tooling\run_fabric_checks.ps1
```

### Apply or update a report theme

```python
# Apply theme to a single report
py -3 products/fabric/powerbi/tooling/apply_report_theme.py products/fabric/powerbi/dist/COM-001_Sales_Performance.Report --theme-name "Aurora_Group"
```

### Audit existing reports for schema drift

```python
# Read-only audit of dist/ — checks schema versions, binding modes, forbidden files
py -3 products/fabric/powerbi/tooling/migration/audit_report_versions.py
```

## Design principles

- **Separation of concerns:** `core/` is tool-agnostic; this implementation consumes it and never modifies it.
- **Single source of truth:** KPI definitions in `core/kpi_catalog/`; action logic in `core/action_codes/`. Reports reference these — they never redefine them.
- **Generated vs. source:** Generated output is in `dist/`; source lives in `orchestrator/`, `tooling/`, `blueprints/`. Never mix them.
- **Silver-first data model:** Semantic models are built from Silver-layer contracts (`core/data_contracts/`). Do not start from Gold-only.

## `dist/` structure

```
products/fabric/powerbi/dist/
  Commercial.SemanticModel/      # Domain semantic model (TMDL)
  Finance.SemanticModel/
  Operations.SemanticModel/
  SupplyChain.SemanticModel/
  Experience.SemanticModel/
  COM-001_Sales_Performance.Report/        # PBIR report per use case
  COM-002_Margin_Price_Performance.Report/
  ...
```

Semantic models and reports live side-by-side. Reports reference their domain model via `definition.pbir → datasetReference.byPath`.
