# tmdl-tom-object-types.md — TOM Object Types Reference

> **Source**: `data-goblin/power-bi-agentic-development` connect-pbid/references/tom-object-types.md
> **Purpose**: Tabular Object Model (TOM) API reference for programmatic semantic model operations via PowerShell and .NET.

---

## Overview

The Tabular Object Model (TOM) is the .NET API for reading and modifying Power BI / Analysis Services semantic models. It operates on the in-memory model loaded in Power BI Desktop or the Fabric XMLA endpoint.

**When to use TOM vs. TMDL files:**
- Use **TOM** for live model introspection, incremental modifications without full re-deploy, and DAX testing against the running engine
- Use **TMDL files** for version-controlled, batch model generation (the framework's primary approach via orchestrator)

---

## Connection Pattern (PowerShell)

```powershell
# Connect to Power BI Desktop's local Analysis Services instance
Add-Type -Path "C:\Program Files\Microsoft.NET\ADAL.Windows\..."
[reflection.assembly]::LoadWithPartialName("Microsoft.AnalysisServices.Tabular") | Out-Null

# Port varies — Desktop shows it in: Help > Diagnostics > Server Name
$server = New-Object Microsoft.AnalysisServices.Tabular.Server
$server.Connect("localhost:54321")

# Get the loaded model
$model = $server.Databases[0].Model
```

**Via XMLA endpoint (Fabric):**
```powershell
$connectionString = "Data Source=powerbi://api.powerbi.com/v1.0/myorg/WorkspaceName"
$server.Connect($connectionString)
```

## Tables

### List All Tables

```powershell
foreach ($table in $model.Tables) {
    Write-Host "$($table.Name) — Columns: $($table.Columns.Count), Measures: $($table.Measures.Count)"
}
```

### Create a Table

```powershell
$table = New-Object Microsoft.AnalysisServices.Tabular.Table
$table.Name = "MyTable"
$table.Description = "Description of MyTable"
$model.Tables.Add($table)
$model.SaveChanges()
```

### Delete a Table

```powershell
$table = $model.Tables["TableName"]
$model.Tables.Remove($table)
$model.SaveChanges()
```

> **Critical**: Always check relationships before deleting a table. Orphaned relationships cause model corruption.

## Columns

### Column Properties

| Property | Type | Notes |
|---|---|---|
| `Name` | string | Display name |
| `DataType` | DataType enum | Int64, Decimal, Double, String, DateTime, Boolean, Binary |
| `SourceColumn` | string | Column name in the source data |
| `SummarizeBy` | AggregateFunction | None, Sum, Min, Max, Count, Average |
| `IsHidden` | bool | Hide from field list |
| `FormatString` | string | e.g. `"#,0"`, `"0.0%"`, `"dd/MM/yyyy"` |
| `DisplayFolder` | string | Use `\` for sub-folders |
| `Description` | string | Tooltip in field list |
| `DataCategory` | string | e.g. `"Address"`, `"City"`, `"Country"` |

### Create a Column

```powershell
$column = New-Object Microsoft.AnalysisServices.Tabular.DataColumn
$column.Name = "Amount"
$column.DataType = [Microsoft.AnalysisServices.Tabular.DataType]::Decimal
$column.SourceColumn = "Amount"
$column.SummarizeBy = [Microsoft.AnalysisServices.Tabular.AggregateFunction]::Sum
$column.FormatString = "#,##0.00"
$column.IsHidden = $false
$table.Columns.Add($column)
$model.SaveChanges()
```

> **Gotcha: RowNumberColumn**. Every table has a hidden `RowNumber` column auto-generated by the engine. When iterating columns, filter it out:
> ```powershell
> $userColumns = $table.Columns | Where-Object { $_.Type -ne [Microsoft.AnalysisServices.Tabular.ColumnType]::RowNumber }
> ```

## Measures

### Measure Properties

| Property | Type | Notes |
|---|---|---|
| `Name` | string | Display name |
| `Expression` | string | DAX expression (no `=` prefix) |
| `FormatString` | string | Required — e.g. `"#,0"`, `"0.0%"` |
| `DisplayFolder` | string | Use `\` for sub-folders |
| `Description` | string | Tooltip in field list |
| `IsHidden` | bool | Hide from field list |
| `KPI` | KPI object | Add KPI metadata (target, status, trend) |

### Create a Measure

```powershell
$measure = New-Object Microsoft.AnalysisServices.Tabular.Measure
$measure.Name = "Total Revenue"
$measure.Expression = "SUMX(Sales, Sales[Quantity] * Sales[UnitPrice])"
$measure.FormatString = "#,##0.00"
$measure.DisplayFolder = "01_Revenue"
$measure.Description = "Total revenue from all sales transactions."

$measuresTable = $model.Tables["_Measures"]
$measuresTable.Measures.Add($measure)
$model.SaveChanges()
```

### Update a Measure Expression

```powershell
$measure = $model.Tables["_Measures"].Measures["Total Revenue"]
$measure.Expression = "SUMX(Sales, Sales[Quantity] * RELATED(Product[ListPrice]))"
$model.SaveChanges()
```

> **Refresh requirement**: Measures require **no data refresh** after modification — they are recalculated at query time.

## Calculated Columns

Calculated columns differ from regular columns — they use a DAX expression and require a data refresh after modification.

```powershell
$calcColumn = New-Object Microsoft.AnalysisServices.Tabular.CalculatedColumn
$calcColumn.Name = "Full Name"
$calcColumn.Expression = "[FirstName] & "" "" & [LastName]"
$calcColumn.DataType = [Microsoft.AnalysisServices.Tabular.DataType]::String
$calcColumn.SummarizeBy = [Microsoft.AnalysisServices.Tabular.AggregateFunction]::None
$table.Columns.Add($calcColumn)
$model.SaveChanges()
# Must refresh: $table.RequestRefresh([Microsoft.AnalysisServices.Tabular.RefreshType]::Calculate)
```

> **Refresh requirement**: Calculated columns require a **Calculate** refresh after creation or modification.

## Relationships

### Relationship Properties

| Property | Type | Notes |
|---|---|---|
| `FromTable` | Table | Fact table (many side) |
| `FromColumn` | Column | Foreign key column |
| `ToTable` | Table | Dimension table (one side) |
| `ToColumn` | Column | Primary key column |
| `IsActive` | bool | Only one active relationship per column pair |
| `CrossFilteringBehavior` | CrossFilteringBehavior | OneDirection, BothDirections, Automatic |
| `Cardinality` | RelationshipEndCardinality | ManyToOne, OneToOne, OneToMany |

### Create a Relationship

```powershell
$rel = New-Object Microsoft.AnalysisServices.Tabular.SingleColumnRelationship

$rel.FromTable = $model.Tables["Sales"]
$rel.FromColumn = $model.Tables["Sales"].Columns["DateKey"]
$rel.ToTable = $model.Tables["Date"]
$rel.ToColumn = $model.Tables["Date"].Columns["DateKey"]
$rel.IsActive = $true
$rel.CrossFilteringBehavior = [Microsoft.AnalysisServices.Tabular.CrossFilteringBehavior]::OneDirection

$model.Relationships.Add($rel)
$model.SaveChanges()
```

> **Gotcha: Relationship batching**. Adding many relationships one at a time triggers engine re-validation after each. For bulk operations, use `$model.BeginUpdate()` / `$model.CommitUpdate()` to batch:
> ```powershell
> $model.BeginUpdate("Bulk relationship add")
> # ... add all relationships ...
> $model.CommitUpdate()
> ```

## Hierarchies

```powershell
$hierarchy = New-Object Microsoft.AnalysisServices.Tabular.Hierarchy
$hierarchy.Name = "Date Hierarchy"

$yearLevel = New-Object Microsoft.AnalysisServices.Tabular.HierarchyLevel
$yearLevel.Name = "Year"
$yearLevel.Column = $model.Tables["Date"].Columns["Year"]
$hierarchy.Levels.Add($yearLevel)

$quarterLevel = New-Object Microsoft.AnalysisServices.Tabular.HierarchyLevel
$quarterLevel.Name = "Quarter"
$quarterLevel.Column = $model.Tables["Date"].Columns["Quarter"]
$hierarchy.Levels.Add($quarterLevel)

$monthLevel = New-Object Microsoft.AnalysisServices.Tabular.HierarchyLevel
$monthLevel.Name = "Month"
$monthLevel.Column = $model.Tables["Date"].Columns["MonthName"]
$hierarchy.Levels.Add($monthLevel)

$model.Tables["Date"].Hierarchies.Add($hierarchy)
$model.SaveChanges()
```

## Roles (Row-Level Security)

### Create a Role

```powershell
$role = New-Object Microsoft.AnalysisServices.Tabular.ModelRole
$role.Name = "Sales Region Europe"
$role.ModelPermission = [Microsoft.AnalysisServices.Tabular.ModelPermission]::Read

# Add table filter
$tablePermission = New-Object Microsoft.AnalysisServices.Tabular.TablePermission
$tablePermission.Table = $model.Tables["Sales"]
$tablePermission.FilterExpression = "[Region] = USERNAME()"
$role.TablePermissions.Add($tablePermission)

$model.Roles.Add($role)
$model.SaveChanges()
```

### Add a Member to a Role

```powershell
$role = $model.Roles["Sales Region Europe"]

$member = New-Object Microsoft.AnalysisServices.Tabular.ExternalModelRoleMember
$member.MemberName = "user@contoso.com"
$member.IdentityProvider = "AzureAD"
$role.Members.Add($member)
$model.SaveChanges()
```

> **Convention**: Roles apply to **dimension tables only** in this framework (see TMDL_Allowed_Subset.md). Never apply RLS directly on fact tables.

## Refresh Requirements by Object Type

| Object Modified | Refresh Required | Type |
|---|---|---|
| Measure expression / format / folder | None | Recalculated at query time |
| Calculated column expression | Yes | `RefreshType.Calculate` |
| Regular column (source column mapping) | Yes | `RefreshType.Full` |
| Partition query | Yes | `RefreshType.Full` |
| Relationship | None (metadata only) | — |
| Role / RLS filter | None (metadata only) | — |
| Hierarchy | None (metadata only) | — |

### Trigger a Refresh via TOM

```powershell
# Calculate only (for calculated columns)
$table.RequestRefresh([Microsoft.AnalysisServices.Tabular.RefreshType]::Calculate)
$model.SaveChanges()

# Full table refresh
$table.RequestRefresh([Microsoft.AnalysisServices.Tabular.RefreshType]::Full)
$model.SaveChanges()
```

## Execute DAX via TOM / ADOMD.NET

```powershell
Add-Type -AssemblyName "Microsoft.AnalysisServices.AdomdClient"

$connection = New-Object Microsoft.AnalysisServices.AdomdClient.AdomdConnection
$connection.ConnectionString = "Data Source=localhost:54321;Catalog=YourModel"
$connection.Open()

$command = $connection.CreateCommand()
$command.CommandText = "EVALUATE ROW(""Revenue"", [Total Revenue])"

$reader = $command.ExecuteReader()
while ($reader.Read()) {
    for ($i = 0; $i -lt $reader.FieldCount; $i++) {
        Write-Host "$($reader.GetName($i)): $($reader.GetValue($i))"
    }
}

$connection.Close()
```

## Common Gotchas

| Issue | Cause | Fix |
|---|---|---|
| RowNumber column in iteration | Every table has a hidden RowNumber column | Filter with `.Type -ne ColumnType.RowNumber` |
| Relationship adds trigger re-validation | Adding relationships one at a time is slow | Use `BeginUpdate()` / `CommitUpdate()` for batch adds |
| Calculated column not updating | Forgot to refresh after expression change | Call `RequestRefresh(RefreshType.Calculate)` and `SaveChanges()` |
| Model save fails on Desktop | Desktop holds an exclusive lock | Ensure no active Desktop operations; retry |
| XMLA connection `401` | Wrong token audience for XMLA | Use `https://analysis.windows.net/powerbi/api` scope |
| Measure visible in Desktop but not Fabric | `IsHidden` set incorrectly in TOM but not in TMDL | Keep TOM and TMDL in sync — regenerate TMDL after TOM changes |
