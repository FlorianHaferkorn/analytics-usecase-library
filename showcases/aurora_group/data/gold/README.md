# Aurora gold layer

Synthetic gold data for the Aurora showcase: dimensions in `dimensions/`, facts in `facts/`. Generated by the orchestrator in `../scripts/generate_aurora_gold.py`; operations and supply_chain are produced by `generate_operations_gold.py` and `generate_supply_chain_gold.py` in this folder.

**Fact coverage check (run from repo root):**

```powershell
py showcases/aurora_group/data/gold/check_fact_coverage.py
```

Reports rows, date range (2020–2024), parquet file count, and flags (SPARSE / MULTI). If supply_chain or operations facts show SPARSE or only 60 dates, re-run the orchestrator or `generate_aurora_gold.py --domain supply_chain` (or `operations`) to refresh. Facts with multiple parquet files require `Table.Combine` in the semantic model partition (see `fact_sales.tmdl`, `fact_experience.tmdl`).

**Modellspalten (A-24, 29.09.2026):** Elf Spalten, die die Semantic Models lesen, schreibt kein Basis-Generator (`dim_customer.Region`, `dim_product.ABC_Class`/`XYZ_Class`, `fact_cost.Material Cost Amount`/`Overhead Amount`, `fact_inventory.COGS Amount`, `fact_procurement.Contract Unit Price`, `fact_action_log.Action Code`/`Responsible Role`, `fact_inventory_snapshot.Reorder Flag`). Die Ableitungen stehen in `_model_columns.py` (deterministisch, ohne globalen Zufallsstrom); Finance-, Supply-Chain- und Gapfill-Generator rufen sie vor dem Schreiben auf. Auf vorhandenem Gold, und nach jedem Lauf des Backbone-Generators (`core/data_contracts/sources/synthetic/generate_gold_layer_contract_v2.py`), ergänzt sie `generate_model_columns.py` (`--tabelle` für einzelne Tabellen; vorhandene Spalten bleiben wertgleich, sonst Abbruch). ABC/XYZ-Schwellen sind vorgelegt, nicht entschieden (siehe Kopf von `_model_columns.py`).

**RLS:** `py showcases/aurora_group/data/gold/generate_security_user_org.py` generates `security_user_org` from the company org profile.

**Commercial:** When you run `generate_aurora_gold.py` with `--domain commercial` (or `all`), it derives `fact_plan_sales`, `fact_customer_events`, and `fact_customer_value` from existing `fact_sales_budget`, `fact_customer_interactions`, and `fact_sales`. Those source tables must already exist (e.g. from a prior full gold run or another pipeline step).
