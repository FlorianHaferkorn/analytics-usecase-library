## Theme 1 — Official-first agent integration & secure, non-technical activation

### How the official bundle is built

- **Microsoft `skills-for-fabric`** ships *skills* (`skills/{name}/SKILL.md`) + *orchestration personas* (`agents/{persona}/AGENT.md`) + shared `common/` + Claude-specific `.claude-plugin/`. "Skills tell the agent **what** to do; tools let the agent **do** it." One command installs the bundle **and auto-registers the Power BI Modeling MCP**. — <https://github.com/microsoft/skills-for-fabric>, <https://learn.microsoft.com/power-bi/developer/agentic/power-bi-agentic-overview>
- **Cross-tool reach is "shims," auto-generated by the install scripts**: root-level `CLAUDE.md`, `.cursorrules`, `.windsurfrules`, `AGENTS.md`, `.mcp.json` are written/picked up on clone (Copilot-CLI-first; VS Code/Claude/Cursor/Codex/Windsurf via shims).
- **Community-on-official layering is already real**: `data-goblin/power-bi-agentic-development` bundles Microsoft Fabric skills alongside its own skills + validation hooks — the exact "extend, don't fork" precedent.

### Claude Code skills/plugins as an open standard

- `SKILL.md` = folder + YAML frontmatter (`name`, `description`, optional `allowed-tools`, `disable-model-invocation`) + `scripts/`/`references/`; body **lazy-loads** only when invoked (unlike always-on `CLAUDE.md`). Dual invocation: model-invoked or `/slash`. Custom commands have **merged into skills**. — <https://code.claude.com/docs/en/skills>
- Follows the **open Agent Skills standard** (<https://agentskills.io>); plugins/marketplaces via `.claude-plugin/plugin.json` + `.mcp.json` + `marketplace.json`. — <https://code.claude.com/docs/en/plugin-marketplaces>

### Single-source → many-agent generators **already exist** (don't reinvent)

- **`rulesync`**, **`ruler`** (also writes `.mcp.json`), **`ai-rulez`**: one canonical source → 20–32 per-tool configs, with a **drift gate** (`generate --check` + `git status --porcelain` in CI; fix-by-regenerate, never hand-edit). — <https://github.com/intellectronica/ruler>, <https://github.com/dyoshikawa/rulesync>
- **`npx skills add owner/repo`** (Vercel, open source) installs skills "into all agents" from any GitHub repo; adopted by Databricks. — <https://learn.microsoft.com/azure/databricks/agent-skills/>
- Cross-agent context conventions: **AGENTS.md** (<https://agents.md/>, ~20k repos) and **llms.txt** (<https://llmstxt.org/>).

### Capability gating — **manifests declare; the host enforces** (important correction)

- Claude Code `settings.json` permissions are a **deny-first allowlist** (`allow`/`ask`/`deny`, evaluated deny→ask→allow; precedence managed > CLI > local > project > user). MCP tools are allowlisted by canonical name `mcp__<server>__<tool>`; org lockdown via `allowManagedMcpServersOnly`, `strictKnownMarketplaces`. — <https://code.claude.com/docs/en/permissions>
- **Default-off network/external**: un-annotated MCP tools default to "destructive, non-idempotent, open-world"; network tools need approval. — <https://modelcontextprotocol.io/specification/2025-06-18/server/tools>, <https://www.anthropic.com/news/our-framework-for-developing-safe-and-trustworthy-agents>
- **Capability manifests (MCPB `manifest.json`, plugin `plugin.json`) *declare* tools/sensitive config for review — they do NOT enforce or sandbox.** Anthropic explicitly does **not** security-audit third-party MCP servers; enforcement is the host's permission engine + human-in-the-loop. — <https://github.com/modelcontextprotocol/mcpb/blob/main/MANIFEST.md>

### Non-technical activation UX (GUI writes config under the hood)

- Cursor *Settings ▸ Rules* writes `.cursor/rules/*.mdc`; VS Code *Configure Chat* writes `.github/copilot-instructions.md`; Claude Desktop *Settings ▸ Connectors* toggles MCP without editing JSON; Claude *Settings ▸ Capabilities ▸ Skills* per-skill on/off (has shipped reliability bugs — pair a toggle with a validation step). — <https://cursor.com/docs/rules>, <https://code.visualstudio.com/docs/agent-customization/custom-instructions>
- Bootstrap without a CLI: GitHub **"Use this template"**, one-click install deeplinks (`cursor://…/mcp/install`), Claude Desktop **`.mcpb`** double-click ("no terminal, no config files"). — <https://www.anthropic.com/engineering/desktop-extensions>

## Theme 2 — Tool-agnostic migration via IR & hub-and-spoke

### The N+M argument is textbook (and citable)

- **Pandoc** = readers → one AST → writers, and states it outright: "a direct conversion between *n* input and *m* output formats would require *n × m* converters; using an intermediate representation reduces complexity to *n + m*." — <https://github.com/jgm/pandoc>, <https://pandoc.org/using-the-pandoc-api.html>
- **LLVM IR** makes the same case (N front-ends + M back-ends share one IR → m+n, plus shared middle optimizations). **Canonical Data Model** integration literature: a hub turns "quadratic" translator complexity "to linearity." — <https://arxiv.org/pdf/1903.10735>

### Real-world BI migration is N×M and governance-heavy

- **Microsoft's own guidance is a *process, not a converter*** — a 5-stage methodology built on rationalization: build "fit-for-purpose reports … rather than an exact replica," because "all BI platforms are different." Pre-migration output is "an initial governance model" + report inventory. — <https://learn.microsoft.com/power-bi/guidance/powerbi-migration-overview>
- **No first-party auto-converter exists**; third-party accelerators (Sparity BIPort, MAQ, Pomerol, REPOZ) **parse the source file's metadata ("read the DNA") → emit target**, almost all **point-to-point, single-direction**, proprietary per tool. — <https://repoz.ai/bi-migration>
- **Rationalization is the real win**: one documented case consolidated **91.5% of reports down to 18** with a governance framework preserving/standardizing KPI logic. "The cheapest thing is nothing" (decommission rather than clone).

### Semantic layers are a hub — but for metrics, not layout

- dbt Semantic Layer/MetricFlow, **Cube**, **AtScale** = "define a metric once, consume everywhere" (the model-once-generate-many hub). — <https://docs.getdbt.com/docs/use-dbt-semantic-layer/dbt-sl>, <https://www.atscale.com/use-cases/universal-semantic-layer/>
- **Crucial limit**: they govern *what a metric means*, **not report layout/visuals/interactivity**. They are not migration tools for dashboards.

## What this means for ALUCA

**Integration / activation**
1. ALUCA's `docs/agent/` SSOT-generator is the **right** pattern — and `ruler`/`rulesync`/`npx skills` prove it; **evaluate adopting one** (esp. `ruler`, which also emits `.mcp.json`) instead of building a bespoke generator. *(Build-vs-buy — open decision.)*
2. Ship ALUCA as a **skills + tools install unit** (one command registers the `generator_core` MCP tools *and* the TMDL/PBIR overlay skills), following the open Agent Skills standard so it stays portable and layerable (data-goblin-on-Microsoft precedent).
3. Add a **drift gate** (`generate --check` + `git status --porcelain`) and a managed-marker `.gitignore` block so generated per-tool configs can't silently diverge.
4. **Correct ADR-0003**: the capability manifest **declares**; real gating is the host's **deny-first permission engine** (`allow`/`ask`/`deny`, `mcp__<server>__<tool>`) + tool annotations (read-only vs destructive) + human-in-the-loop. Ship external/network tools in `ask`/`deny` by default.
5. Studio = GUI that writes the manifest under the hood — well-precedented (Cursor/VS Code/Claude connectors). Pair each toggle with a validation step (avoid the known GUI-toggle reliability bug).

**Migration**
6. Frame `DashboardSpec` explicitly as **"the Pandoc AST of dashboards"** — a proven, citable N+M architecture; ingest = one new *reader*.
7. Ingest as **"read the DNA" metadata-parsers → IR**, and **separate semantics-readers (reconcile to the KPI catalog) from layout-readers (map to visuals)** — different fidelity profiles, different review flows.
8. Make ingest **lossy-but-reviewable** (emit a per-import fidelity/diff report) and **reconcile incoming metrics against the catalog** (match / propose-new / flag-duplicate) with a **fast-path** so governance doesn't stall the migration.
9. Adopt the **rationalization framing** (inventory → prioritize-by-usage → decommission → consolidate), not "import everything."
10. **Don't be a semantic layer; integrate with one** — optionally bind `DashboardSpec` metrics to a dbt/Cube definition (metric governed upstream, layout/use-case governed by ALUCA).

## Gaps / risks
- Power BI Agentic, the Modeling MCP, and Claude GUI skill toggles are **preview** — pin versions, expect churn.
- "Optimized for Copilot CLI, shims for the rest" → full-fidelity may lag on Claude/Cursor; the open standard mitigates but doesn't erase this.
- Manifests are review metadata, **not a sandbox** — never present them as enforcement.
- Ingest parsing of `.twb`/`.qvf`/LookML is brittle and versioned (the per-version tax accelerators already pay); fidelity loss is structural, not a bug.
